# 1. React

React는 사용자 인터페이스(UI)를 만들기 위한 JavaScript 라이브러리이다. 화면을 여러 개의 컴포넌트로 나누어 개발할 수 있어 복잡한 UI를 관리하기 쉽다.

### React의 특징

1. **단방향 데이터 흐름**
   - 데이터가 기본적으로 부모 컴포넌트에서 자식 컴포넌트 방향으로 흐른다.
   - 자식 컴포넌트가 부모의 상태를 직접 변경하는 방식은 사용하지 않는다.
   - 필요한 경우 부모가 함수를 자식에게 전달하고, 자식이 해당 함수를 호출하는 방식으로 부모와 상호작용할 수 있다.

2. **JSX 사용**
   - React에서 사용하는 JavaScript 확장 문법이다.
   - HTML과 유사한 형태로 UI를 작성할 수 있어 화면 구조를 이해하고 작성하기 편리하다.

3. **상태 관리 기능 제공**
   - React는 컴포넌트의 상태를 관리할 수 있도록 다양한 Hook을 제공한다.
   - 상태가 변경되면 해당 상태를 사용하는 UI가 다시 렌더링된다.

4. **풍부한 생태계**
   - React를 기반으로 다양한 라이브러리와 개발 도구를 함께 사용할 수 있다.
   - 라우팅, 상태 관리, API 통신, UI 구성 등 필요한 기능을 외부 라이브러리와 조합하여 개발할 수 있다.

# 2. Vite

Vite는 웹 개발을 위해 설계된 차세대 프론트엔드 빌드 도구이다.

### Vite의 특징

1. **빠른 개발 환경**
   - 개발 서버가 빠르게 실행된다.
   - **HMR(Hot Module Replacement)**을 제공하여 코드를 수정했을 때 전체 페이지를 다시 로드하지 않고 변경된 부분을 빠르게 반영할 수 있다.

2. **간편한 설정**
   - 기본 설정만으로 React 프로젝트를 쉽게 생성하고 바로 개발을 시작할 수 있다.

3. **다양한 프레임워크 지원**
   - React뿐만 아니라 여러 프론트엔드 프레임워크와 라이브러리를 사용할 수 있다.

### 실행 방법

```bash
npm run dev
```

실행 후 브라우저에서 다음 주소로 접속한다.

```text
http://localhost:5173
```

# 5. React 컴포넌트

컴포넌트는 React에서 화면을 구성하는 독립적인 최소 단위이다.

### 컴포넌트의 특징

1. 화면을 구성하는 최소 단위로 사용할 수 있다.
2. 자신만의 상태를 가질 수 있으며 이를 이용해 데이터를 관리하고 동적인 UI를 구성할 수 있다.
3. 독립적으로 동작하고 렌더링되는 앱의 한 조각이다.
4. 기본적으로 부모 컴포넌트에서 자식 컴포넌트로 데이터를 전달하는 **탑다운(Top-down) 방식**을 사용한다.
5. 자식 컴포넌트에서 부모 컴포넌트로 데이터를 전달해야 하는 경우 부모가 함수를 전달하고 자식이 이벤트를 통해 해당 함수를 호출하는 방식을 사용할 수 있다.

### 컴포넌트 종류

React 컴포넌트는 과거에 **함수형 컴포넌트**와 **클래스형 컴포넌트**로 나뉘었다.

현재는 Hook을 사용할 수 있는 **함수형 컴포넌트가 일반적인 표준 방식**으로 사용된다.

# 6. 컴포넌트 제작 시 주의할 점

React 컴포넌트가 반환하는 JSX는 반드시 **하나의 최상위 요소**로 감싸져 있어야 한다.

예를 들어 다음처럼 최상위 요소가 2개이면 오류가 발생할 수 있다.

```jsx
return (
  <h1>Hello</h1>
  <p>React</p>
);
```

최상위 요소가 여러 개 필요하다면 **React Fragment**를 사용할 수 있다.

```jsx
return (
  <>
    <h1>Hello</h1>
    <p>React</p>
  </>
);
```

Fragment를 사용하면 별도의 실제 HTML 요소를 추가하지 않고 여러 요소를 하나로 묶을 수 있다.

# 7. JSX

**JSX = JavaScript XML**

JavaScript 코드 안에서 HTML과 유사한 문법으로 UI를 작성할 수 있도록 만든 React의 확장 문법이다.

### JSX의 특징

1. JavaScript 안에서 HTML과 유사한 코드를 작성할 수 있다.
2. UI 구조를 직관적으로 표현할 수 있어 코드의 가독성과 작성 편의성이 높아진다.
3. JSX는 반드시 하나의 최상위 요소로 감싸야 한다.
4. XML 문법의 영향을 받기 때문에 여는 태그와 닫는 태그를 정확하게 작성해야 한다.
5. 일부 속성은 JavaScript와의 충돌이나 JSX 규칙 때문에 다른 이름을 사용한다.

| HTML | JSX |
|---|---|
| `class` | `className` |
| `for` | `htmlFor` |

6. 이벤트 핸들러 속성은 **카멜 케이스(camelCase)** 형식으로 작성한다.

| HTML 방식 | JSX 방식 |
|---|---|
| `onclick` | `onClick` |
| `onchange` | `onChange` |

# 8. Props

**Props(Properties)**는 컴포넌트 사이에서 데이터를 전달하기 위한 객체이다.

### Props의 특징

- 부모 컴포넌트가 자식 컴포넌트로 데이터를 전달할 때 사용한다.
- 하나의 값뿐만 아니라 배열, 객체, 함수 등 다양한 데이터를 전달할 수 있다.
- Props는 자식 컴포넌트에서 직접 수정하지 않는 **읽기 전용 데이터**이다.
- 부모 컴포넌트가 전달할 값을 결정한다.

예를 들어 부모가 다음과 같이 값을 전달할 수 있다.

```jsx
<Child name="주상혁" />
```

자식 컴포넌트에서는 Props를 받아 사용할 수 있다.

```jsx
function Child(props) {
  return <h1>{props.name}</h1>;
}
```

즉, **부모 → 자식 데이터 전달**이 Props의 기본 역할이다.

# 9. 이벤트 처리

React에서는 사용자의 클릭, 입력, 변경 등의 동작을 이벤트로 처리한다.

### Synthetic Event

React는 브라우저의 이벤트를 처리하기 위해 **SyntheticEvent(합성 이벤트 객체)**를 제공한다.

- React가 제공하는 이벤트 객체이다.
- 브라우저마다 이벤트 처리 방식이 다른 부분을 추상화하여 일관된 방식으로 이벤트를 사용할 수 있도록 한다.
- 브라우저 호환성에 대한 부담을 줄이고 이벤트 처리 로직에 집중할 수 있다.

### 자식 → 부모 데이터 전달

React의 기본 데이터 흐름은 부모에서 자식 방향이지만, 이벤트와 함수를 이용하면 자식의 데이터를 부모에게 전달할 수 있다.

흐름은 다음과 같다.

```text
부모 컴포넌트
   ↓ 함수 전달
자식 컴포넌트
   ↓ 이벤트 발생 + 함수 호출
부모 컴포넌트에서 데이터 처리
```

부모가 함수를 Props로 전달하면 자식은 이벤트가 발생했을 때 해당 함수를 호출할 수 있다. 이때 함수의 매개변수를 이용하여 자식에서 부모에게 데이터를 전달할 수 있다.

# 10. 컴포넌트 모듈화

### 컴포넌트 모듈화가 필요한 이유

간단한 프로젝트에서는 `App.jsx` 하나에 모든 컴포넌트를 작성해도 문제가 크지 않다.

하지만 화면이 복잡해지고 컴포넌트와 코드가 많아지면 하나의 파일에서 모든 코드를 관리하기 어려워진다.

따라서 기능이나 화면 단위로 컴포넌트를 분리하여 각각의 파일로 관리하는 **컴포넌트 모듈화**가 필요하다.

### 모듈화의 장점

- 코드의 가독성이 좋아진다.
- 파일별 역할을 구분하기 쉽다.
- 특정 컴포넌트를 재사용하기 편해진다.
- 유지보수와 수정이 쉬워진다.
- 여러 컴포넌트를 독립적으로 관리할 수 있다.

예시 구조:

```text
src/
├── App.jsx
├── components/
│   ├── Header.jsx
│   ├── Main.jsx
│   └── Footer.jsx
└── main.jsx
```

## 💡 학습 포인트

React에서는 화면을 하나의 큰 코드로 작성하기보다 **컴포넌트로 나누어 관리**하는 것이 중요하다.

또한 React의 기본적인 데이터 흐름은 **부모 → 자식**이며, 자식에서 부모로 데이터를 전달해야 할 때는 **부모가 함수를 전달하고 자식이 이벤트를 통해 호출하는 방식**을 사용한다.

JSX는 HTML처럼 보이지만 JavaScript 안에서 사용하는 문법이므로 `className`, `onClick`처럼 JSX만의 규칙을 지켜야 한다.
